2. **Interruption/requeue recovery is not documented or deterministic end-to-end.** The kit has good opt-in checkpoint discovery, but no `--requeue`/`--no-requeue`, restart-count handling, pre-timeout signal, or signal-triggered checkpoint. If Slurm automatically requeues an interrupted job, it restarts with `RESUME=0`; once any checkpoint exists, the script exits at its checkpoint-exists guard instead of continuing. The experiment docs merely say “resume-aware” and never state what the operator does after an hour-30 failure. [plan:149-154](https://github.com/Yixun-Hu/FLAC/blob/2a504fed6697d138dbf011660864f3335a1b71c9/worklog/worklog_yixun/exp_16_della_vanilla_repro_claude/plan_della_vanilla_repro.md#L149-L154), [train:18-26,214-241](https://github.com/Yixun-Hu/FLAC/blob/2a504fed6697d138dbf011660864f3335a1b71c9/worklog/worklog_yixun/exp_16_della_vanilla_repro_claude/della_train.sbatch#L18-L26), [submit:12-18](https://github.com/Yixun-Hu/FLAC/blob/2a504fed6697d138dbf011660864f3335a1b71c9/worklog/worklog_yixun/exp_16_della_vanilla_repro_claude/della_submit.sh#L12-L18).

   Before launch, record the actual cluster `PreemptMode`/`JobRequeue` policy and choose deterministic behavior—preferably `--no-requeue` plus manual recovery, or an explicitly reviewed restart handler. The runbook should say:

   1. Confirm the previous job is terminal and inspect its log/accounting state.
   2. Validate the newest checkpoint is readable, belongs to exp_16, and has `step < 67500`.
   3. If it exists, submit `della_submit.sh train --resume --time <remaining time plus margin>` with the measurement closure unchanged and pushed.
   4. If no checkpoint exists, resubmit **without** `--resume`.
   5. Record the new job/W&B run and disclose that resumed execution is not bit-exact.

   Princeton documents a 72-hour `gpu-medium` limit and says time-limit overruns are killed, but does not publicly promise automatic requeue or characterize `gpu-medium` as preemptible. [Della QOS table](https://researchcomputing.princeton.edu/systems/della), [Princeton Slurm guidance](https://researchcomputing.princeton.edu/support/knowledge-base/slurm).
