## Verbatim review (as pasted by Yixun)

> My assessment: the plan can produce a clean B-F frame-averaging port, but I would not approve Rev 2 as written. I recommend "REQUEST CHANGES" and a Rev 3.
>
> I verified that the core computation path is complete: `FA config → cylindrical pose features → C4 joint depth/pose rotation → rerun only the two ViT conditioners → average → train/validation/test dispatch → DDP + SyncBN + gradient checkpointing → evaluation`. Excluding fine-tuning, CylViT, batched orbit, yaw augmentation, and later experiments is appropriate for an as-run B-F port.
>
> Required Rev 3 changes:
>
> 1. **Make evaluation protocol mismatches fail closed in code.** `eval_FLAC.py` currently defaults independently to `cond_method="vanilla"`, even when the config/checkpoint was trained with `fa_invariant`. This exact mistake already happened: B-F 40k gave approximately `8.190 / 0.9804 / 38.811 / R@1 5.302` under correct FA evaluation, but `10.674 / 2.0809 / 80.106 / R@1 0.710` under accidental vanilla evaluation. It caused the exp_09 protocol error and the retraction of an exp_07 conclusion. After `torch.load`, but before model/GPU construction: read the checkpoint's embedded `model_config.training`; compare trained `cond_method` and `frame_avg_angles` with runtime values; raise on mismatch; permit deliberate off-diagonal experiments only through an explicit escape hatch such as `--allow-conditioning-override`; record both trained and runtime methods in output metadata. A README warning is not sufficient.
>
> 2. **Fix tests that would otherwise pass or skip without testing the intended behavior.** C10b currently depends on the excluded `worklog/.../FLAC_AR_BV.json`; in the clean repo, all DINO-backed tests would silently skip. Use the in-tree `src/configs/model_configs/FLAC/AR/FLAC_AR.json` and inject the checkpointing flag in memory. C7b's fake evaluation uses an empty dataloader, so it never executes rotation or the FA branch. Add a one-batch spy test proving rotation happens first, then `invariant_conditioning`; also prove vanilla calls the ordinary conditioner. D9 may remove `yaw_transform_consistency`, but C2 must add a real physical sign test for roll direction, `alpha_eff`, pose/depth co-rotation, and non-mutation. The existing source test only checks that depth changed. D8 should retain a compact Trainer-kwargs parity test covering devices, strategy, precision, accumulation, gradient clipping, callbacks, and logger. That is behavioral protection, not merely a development canary. Keep the SyncBN CLI override test. C10b gradients should use the source test's `allclose(atol=1e-6, rtol=1e-5)` contract. Only the `state_dict` is byte-identical.
>
> 3. **Make C1's file inventory explicit.** "14 configs / 74 lines" is internally inconsistent: AR-only portability is 14 files and roughly 56 diff lines; including the five HAA configs gives 19 files and roughly 76 diff lines. Choose one scope and list every file. In either case, include `AGREE/AGREE/model_configs/dinoV3.json`. Its VAE path must change from `FLAC/weights/FLAC/VAE.ckpt` to `weights/FLAC/VAE.ckpt`, or AGREE metric construction will fail. Add JSON-parse and AGREE-import smoke tests.
>
> 4. **Make C11's config test type-strict and offline-safe.** There are four changed leaf paths: `training.cond_method`, `training.frame_avg_angles`, `source_vit.config.gradient_checkpointing`, `context_poses_vit.config.gradient_checkpointing`. Check both conditioner IDs explicitly and require literal booleans/floats. The normal unit test should not download or fully build DINO; reserve the real build for the offline-cache smoke test.
>
> 5. **Make end-to-end acceptance deterministic.** Do not leave "exp_09 Fw or B-F 40k" undecided. Prefer the B-F 40k checkpoint because it directly validates the target method. Pin: checkpoint path and SHA-256; dataset/K; evaluation seed; expected metrics JSON; per-metric tolerances. Running only `acousticroom_unseeneval.json` at seed 42 is a K=8/s42 calibration, not a reproduction of the complete K={1,8}, seeds 42–46 Table-1 protocol. Either rename the check or run the full matrix.
>
> 6. **Define the supported inference API.** `ConditionedDiffusionModelWrapper.generate()` reaches `src/inference/generation.py`, which still directly calls `model.conditioner(...)`; therefore it silently uses vanilla conditioning even for an FA-configured model. Either route it through a shared conditioning dispatcher; or explicitly document that the clean port supports `train.py` and the evaluation entry points only, while `.generate(conditioning=...)` requires precomputed invariant conditioning tensors. `eval_pl.py` should likewise record method/angles and use the same trained-as guard, or explicitly reject FA and direct users to `eval_FLAC.py`.
>
> 7. **If claiming exact B-F reproduction, pin the DINO initializer.** The actual launch pinned revision `114c1379950215c8b35dfcd4e90a5c251dde0d32`. The clean config/factory should pass that revision. Without it, the result is a method reproduction, not an exact B-F recipe reproduction.
>
> The 14-commit structure can remain. However, C5b and C10b are tests-only commits after their implementation, so change "tests never land after code" to "core tests land with the code; extended tests immediately follow." Treat the ≈200-line figures as projections until each real commit is measured, and do not remove behavioral coverage merely to meet the line target.
>
> My decision recommendations: D1 and D3–D7: approve with the corrections above. D8: conditionally approve. D9: approve only after adding the independent physical rotation-sign test.
