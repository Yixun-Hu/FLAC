## 1. How to run

```bash

```

**What every step does**
- It refuses with **exit 2** in two cases, before running anything: the tracked tree is dirty, or one of its outputs
  already exists. Run directories, dump directories, selector vectors, gate records and verdicts are all write-once.
- It writes `loc_efficiency_<timestamp>_<step>.log` in this folder. The log holds `HEAD <sha>`, the exact command
  (`printf %q`), the command's output and `EXIT <code>`.
- It returns **the command's own exit status**. This is `PIPESTATUS[0]`; nothing masks it.
- `run` and `phase` stop at the first non-zero step and print `STOPPED at <step> (exit <code>)`.

**Fixed environment.** The script exports `PYTHONDONTWRITEBYTECODE=1` and `HF_HUB_OFFLINE=1`, and unsets
`PYTHONPATH`. Model steps run with `CUDA_VISIBLE_DEVICES=0` and `--device cuda:0`, one process at a time. CPU steps
hide CUDA.

**Never commit in this checkout while a step runs.** Timed runs bind their identity to the checkout at start.

## 2. Rules that bind every model step (the runner enforces them; the script only spells them)

- **No-flash.** Every model step runs `overlays/no_flash/exp37_no_flash_launch.py` with
  `--require-attention-backend sdpa`. The launcher refuses with exit 86 unless SDPA is selected. The run identity
  records the overlay and launcher digests.
- **Timed steps.** Their flags are `--synchronize-latency --warmup-query-count 1 --measure-core-forward`.
  - The runner starts the **run-bound co-tenancy monitor** (`tools/exp37_cotenancy_monitor.py`, stdlib only,
    `python -I -B`) in `<run>/cotenancy/`. It samples about once per second until the run ends. Each sample records
    nvidia-smi compute apps, foreign CPU from `/proc`, every foreign process and the exp_36 host gate. Each sample is
    hash-chained and bound to the run manifest.
  - The runner writes the markers `gpu_resident`, `timed_start` and `timed_end`.
  - A timing is publishable only if all of the following hold (`exp37_cotenancy.monitor_verdict`):
    - no observation gap above 3 s;
    - every nvidia-smi query succeeded;
    - the run's own pid was on its card, and nothing else was, from residency to the end;
    - exp_36 never appeared;
    - mean foreign CPU over the timed interval was ≤ 4 cores (**a Planner decision; see §5**);
    - the run has its three hashed host records (start / loaded / end), bound to it.
  - Timed steps **never dump** and **never resume**.
- **Accuracy-only steps.** They run untimed and pass `--dump-waveforms /media/diskstation/yixunhu/FLAC/exp37_pred_waveforms/<run stem>`
  (announcement 08). The dump holds the exact scored `[M,1,10240]` float32 tensors, one `.npy` per query, plus a hashed
  manifest. That manifest is bound to the run manifest, checkpoint, seed and backend, and covers every query. The
  dump directory must not exist yet. Accuracy-only runs never resume.
- **Replay steps** (`--replay-of <timing run>`). These are untimed and produce no stage split.
  - The runner refuses unless the replay's identity equals the timing pass's identity, ignoring the timing flags.
  - It regenerates with the same seeds, candidates and batches. A c2f replay follows the c2f pass's own batch plan.
  - It dumps the waveforms, and refuses unless every query's similarities equal the timing run's **bitwise**.
- **Host gate.** The gate steps (`P0.4`, `SEL.0`, `B1.0`, `B2.0`, `B3.0`) write a hashed record. They exit 3 while
  any process has its cwd or argv under `~/codespace/exp-36-yaw-c4-spread` or `~/codespace/.exp36-baseline-H35`, and
  that stops the phase. The monitor re-checks the gate on every sample.
- **Hard stops.**
  - G0 exits 1 (FAIL) or 2 (REFUSED).
  - Any step exits non-zero.
  - Any timing turns out unattested. The summaries then write only a `*.DIAGNOSTIC.*` file and exit 3. Re-run that
    pass into a fresh directory. Never publish the diagnostic.

**GPU time.**
- Required total: about 10–11 h plus about 1–2 h of start-ups (roughly 60 GPU steps × 1–3 min).
- With XR: about 5 h more.
- The walls are estimates scaled from the bundle's per-candidate costs.

**Order.** Timed phases first, while the host is quiet (after exp_36 has left). The untimed phases can follow in any
order.

**Dump volume on the NAS.**
- Required: about 43 GB. That is 0.5 m: 46,301 pairs × 21 runs; 0.75 m: 11,537 × 6; G0: 27 × 3; at 40 KB per pair.
- XR adds about 54 GB.
- The NAS has 15 TB free.

## 7. Outputs and exit codes

- **Exit codes.**
  - The B1 summary (`B1S.*`) and the aggregator (`AGG.run`) exit **0** only when every timing is attested; they then
    write the publication files.
  - **3** means at least one timing is unattested. The tool then writes only `<name>.DIAGNOSTIC.json` and
    `<name>.DIAGNOSTIC.md`, with every reason listed, no frontier and no figure.
  - **2** means a coverage or spec gap, or an existing output. Nothing is written.
- **Inventory.** Every summary carries an inventory: input manifests; selector bindings and monitor heads; run,
  replay and dump manifests; per-query artifacts; attestations; the pinned exp_23 summary (`674998f9…`) and bundle
  latency CSV (`3cac4a9c…`); and the synthesis files.
- **Planned spec.** The complete planned spec, with synthesis pending, is committed as `b2b3/b2b3_spec.planned.json`.
  It was produced by the builder from `b2b3/b2b3_inputs.json`.
