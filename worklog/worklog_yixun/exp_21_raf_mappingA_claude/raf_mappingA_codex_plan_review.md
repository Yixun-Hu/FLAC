1. **M1 — blocking. Existing audio cannot support this protocol.** The plan says Mapping-A can reuse the published scaled WAVs without resampling ([plan §4.1](</home/yixunhu/codespace/exp-21-raf-mapping-a/worklog/worklog_yixun/exp_21_raf_mappingA_claude/plan_raf_mappingA.md:22>)), but exp_19 published only the 21 selected tx-groups per room; reserve-group audio was deliberately omitted ([prepare_data.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/data/RAF/prepare_data.py:1136>), [selection/write path](</home/yixunhu/codespace/exp-21-raf-mapping-a/data/RAF/prepare_data.py:1282>)). The committed selected groups provide at most seven groups in any current placement bucket, below Mapping-A’s ≥9 requirement. Moreover, exp_19’s ×3 amplitude decision was audited over only 1,512 written files, not arbitrary Mapping-A captures; the readback sample contains raw peaks for which ×3 could clip.  
   **Fix:** build and publish the exact union of Mapping-A target and context captures—up to 10,368 unique WAVs—by resampling raw 48 kHz audio to 22,050 Hz float32. Run a pre-publication amplitude audit on that exact union; accept ×3 only if every file passes no-clipping, finite/nonzero, and loader-silence gates. Otherwise stop for a registered amplitude-policy decision; never drop or substitute affected items. Bind raw capture IDs, output hashes, scalar, and the exp_19 generation for any genuinely reused files.

2. **M2 — blocking. “Placement” and same-mic correspondence are not sufficiently defined.** The inherited `_placement_key` is merely a receiver-centroid rounded independently to 1 cm and is explicitly “informational” ([prepare_data.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/data/RAF/prepare_data.py:272>)). It can split one re-occupation across adjacent rounding bins or merge nearby placements. Therefore the quoted 139/121 counts and the FPS population are not yet validated physical placements. A 2 cm cutoff alone also does not prove a unique 36-way microphone correspondence, and 2 cm is not acoustically negligible for waveform metrics.  
   **Fix:** preregister a deterministic placement/correspondence algorithm before FPS: cluster groups without transitive chaining; select a deterministic medoid/template; solve a 36×36 one-to-one assignment for every tx-group; require unique matches, an ambiguity margin relative to the next-nearest mic, and a tolerance well below half the minimum inter-mic spacing. Record matched-displacement p50/p95/max and rigid-array residuals. Treat 2 cm only as an anomaly cap, not evidence of exact co-location. Exclude a failing tx-group before eligibility; require ≥9 passing, source-distinct groups; never drop individual mics/items. Any correspondence violation after publication must abort the publication, not reduce 1,152 silently.

3. **M3 — blocking. The signs are mostly right, but Rev 1 does not exactly mirror `AR_md.py` under approximate re-occupation.** AR constructs the target as `target_tx − target_rx` ([AR_md.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/src/configs/dataset_configs/custom_metadata/AR_md.py:29>)), each context pose as `context_tx − that context RIR’s own rx` ([AR_md.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/src/configs/dataset_configs/custom_metadata/AR_md.py:120>)), and loads depth for the target receiver index ([AR_md.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/src/configs/dataset_configs/custom_metadata/AR_md.py:47>)). Rev 1 instead subtracts one nominal `pos(m)` from every context. Those coincide only when receivers are exactly identical, which RAF does not guarantee.  
   **Fix:** pin:
   `source = tx*_p − rx_target_p`;  
   `context_pose_j = tx_j_p − rx_context_capture_j_p`;  
   `depth = panorama(rx_target_p)`;  
   and copy these into the corresponding `*_vit` fields. Record every `rx_context_capture_j − rx_target` displacement. Describe RAF Mapping-A as an approximate same-listener realization bounded by the correspondence audit—not “exact AR relation.” If a common target-origin approximation is intentionally preferred, register it as a deviation and quantify it against the actual-AR formula.

4. **M4 — blocking. The proposed publication scheme can invalidate Mapping-H.** The current publisher recognizes only `prepare` and `depth` marker kinds and uses one `raf_publish_manifest.json` per root ([publish.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/data/RAF/publish.py:23>)). Publishing another flavor into an overlapping split, runtime, or depth root can overwrite a manifest or supersede a marker—the exact exp_19 r4 T4 failure mode. Rev 1 promises “its own marker kind” but does not list the required `publish.py`/verifier work among its code surfaces.  
   **Fix:** give Mapping-A disjoint split/runtime/depth roots plus flavor-scoped pointer and markers, e.g. `mappingA_prepare` and `mappingA_depth`. Register exact canonical identities for placement count, K, matching tolerance/algorithm version, correspondence digest, capture/audio digest, renderer parameters, and readback digest. `RAF_A_md` must verify the Mapping-A combined publication while `RAF_md` continues verifying Mapping-H. Add H→A, A→H, republish, and injected-crash composition tests proving both flavors remain simultaneously valid.

5. **M5 — blocking. “The only integrity surface is identity” is too narrow, and the proposed audit does not prove the Mapping-A relation.** The existing stream hash records target relpath and context capture IDs ([eval_FLAC.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/eval_FLAC.py:609>)); it does not itself prove that contexts are the matched mic, belong to other source groups, respect the displacement bound, or use the attested poses/depth generation.  
   **Fix:** add a static manifest validator requiring 1,152 unique targets, exactly eight distinct contexts each, no target capture or target full-pose group in context, matched mic slot, correspondence bound, and no duplicate target/source atom. If “unseen source position” is claimed, exclude every context group at the target xyz even when quaternion differs; otherwise call it unseen full pose. At runtime require exact stream count and positional audit, schema-2 capture IDs, identical `input_hash` across all 15 P1/BF/YAW cells and seeds, and identical Mapping-A publication generations/digests. For the optional exp_19-finetuned row, publish capture-, tx-pose-, xyz-, and placement-level overlap with exp_19 training supports; any overlap means that row is not an unseen-source result and must remain a separately labelled transfer diagnostic.

6. **M6 — blocking. The Mapping-A versus exp_20 Mapping-H “isolates” claim is not licensed.** Exp_20 uses 768 Mapping-H targets selected as 24 held-out receivers in 32 tx-groups. Rev 1 proposes 1,152 targets from different placement/source selection, with all 36 mics, different contexts, and listener rather than transmitter depth. Same checkpoints and rooms do not control target-RIR difficulty, source distribution, listener distribution, or geometry. Thus the delta cannot be attributed specifically to source generalization versus receiver interpolation.  
   **Fix:** make the primary inference cross-arm comparisons within each protocol. Present exp_20 only as a non-matched descriptive reference, explicitly stating that absolute Mapping-A/H deltas are confounded by item construction. If a mapping contrast is required, construct an additional preregistered H/A pair over the same target RIR captures and analyze paired placement-cluster contrasts; it would be a new matched protocol, not the existing exp_20 rows.

7. **M7 — blocking. The effective sample size and uncertainty plan are unsound.** The 1,152 items consist of only 32 placements and 32 held-out target poses; the 36 mics within each placement share target, context pool, room, and array. Five diffusion seeds estimate generation-noise variability only, not dataset or room uncertainty. `--record-per-scene` supplies room results, but Rev 1 has no per-placement metric collection.  
   **Fix:** make placement the clustering unit. Report every placement, each room separately, and the fixed two-room macro. For arm contrasts, pair exact items/seeds, aggregate within placement first, then use a room-stratified cluster bootstrap or paired placement-level randomization interval. Report seed SD separately as Monte Carlo variability. Do not calculate item-i.i.d. intervals with n=1,152, and do not generalize to a population of rooms from two fixed rooms. Add a per-placement collection surface or retain predictions sufficient to calculate it.

8. **M8 — should-fix. “FPS-last target” changes the estimand.** The final member of a full FPS traversal is not generically representative; it preferentially selects a poorly covered/outlying source. Together with one target per placement, the experiment measures 32 spatial-stress targets, not RAF unseen-source performance broadly. “FPS-last” is also ambiguous between full tx pose and unique xyz.  
   **Fix:** either label the estimand “spatially extreme held-out source” and report target-to-context/source distributions, or choose target poses by a preregistered stable uniform hash while retaining FPS only for placement coverage. Clarify full-pose versus xyz identity and consider balanced multiple target sources per placement if the intended claim is general unseen-source performance.

9. **M9 — should-fix. BF’s `fa_invariant` is applicable, but listener-depth reuse needs explicit adaptation and tests.** The FA implementation is AR-native here: it makes target/context poses cylindrical about the target-source azimuth and rotates listener-centered depth with the `*_vit` poses ([yaw_rotation.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/src/data/yaw_rotation.py:389>)). However, the current depth CLI hardcodes `tx_xyz_p`, raw transmitter height, and receiver sightlines ([render_depth.py](</home/yixunhu/codespace/exp-21-raf-mapping-a/data/RAF/render_depth.py:981>)); merely adding “positions-from mappingA” would apply the wrong QA provenance at a listener.  
   **Fix:** parameterize the renderer with target receiver position, independent raw RAF receiver height, and transmitter endpoints for the recorded sightline diagnostic. Require listener-map containment/nadir/bounds/scale gates, exact no-flipud equirect convention, a real conditioner pass for both vanilla and FA, and a C₄ rotation-invariance test on Mapping-A metadata.
