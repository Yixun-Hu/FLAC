# plan_raf_finetune — exp_19: FLAC finetune on RAF (paper-parity with the HAA protocol)

**Author:** Claude Fable 5 (Planner seat, second session). **Rev 2, 2026-08-19** — folds all 16 Codex findings (`raf_finetune_codex_plan_review.md`, C1–C16; disposition in worklog; one reasoned deviation on C8's frame-avg literal, noted in §6). Status: **awaiting Yixun approval before any implementation**.

## 1. Objective

Adapt RAF (2 real rooms: EmptyRoom, FurnishedRoom) into FLAC's pipeline and finetune the AR-pretrained released FLAC on it in the spirit of the paper's HAA protocol, then evaluate zero-shot vs finetuned with the applicable metric suite. Scope per Yixun 2026-08-19: paper-parity finetune first; localization on RAF and non-Vanilla arms are separate later experiments.

## 2. Data structure (measured on the landed EmptyRoom, 2026-08-19)

- `archived/<Room>/data/<6-digit id>/{rir.wav, tx_pos.txt, rx_pos.txt}`; `metadata/all_{tx,rx}_pos.txt` (line i ↔ id i; the all_rx file has one extra trailing line vs all_tx — resolved fail-closed at readback). RIR: mono 48 kHz float32 WAV, 1.5 s, peak ~0.01. tx = quaternion(4)+xyz(3); rx = xyz. World: X front, Y up, Z left, y=0 ground, meters.
- **Capture topology (measured):** a rigid **36-microphone array** (bbox 1.11×1.24×1.11 m, max pairwise 1.46 m — identical for every group) was placed at **139 placements**; at each placement the speaker took several poses (**median 9 tx, max 108**); every full tx pose (quat+xyz line) has **exactly 36 captures** ⇒ 1,319 (tx-pose → placement) groups × 36 = 47,484. Receiver positions essentially never repeat exactly (47,481 unique; placements re-occupied to sub-cm).
- **Readback rung (fail-closed, pre-training):** FurnishedRoom structural equality (same schema; exactly-36 invariant or the deviation recorded and handled); per-file vs `all_*` consistency + the off-by-one; quaternion column-order verified against the RAF release (wxyz vs xyzw never guessed); **quat-per-xyz audit** (C2: are there same-xyz different-orientation tx?); duplicate `(tx,rx)` capture audit; amplitude distribution vs processed HAA/AR incl. count under the loader's −60 dB silence threshold (C12); **onset analysis** (C5): regress detected onset vs geometric distance/c, estimate hardware latency + residuals, compare AR/HAA conventions, and preregister the (constant-only) delay handling; **T30 validity** on the 10,240-sample crop vs the full 1.5 s — if truncation invalidity is substantial, T60 is demoted from headline with the rule stated in advance (C5).

## 3. Conditioning mapping (C1/C2 folded)

Two mappings exist in RAF's topology; **v1 registers Mapping H** (it is the HAA-parity Yixun asked for), Mapping A is offered as the scientifically stronger follow-up (§10.1):

- **Mapping H (HAA-style, registered v1):** frame centered at the source (tx); the receiver position goes into the `source`/`source_vit` slots; context = K=8 **other microphones of the same (tx-pose, placement) group**, drawn from that group's 12-mic train support; depth panorama rendered at tx. Reuses `HAA_md.py` helper semantics. **Honest framing (stated in all artifacts): the test receivers lie inside the same 1.46 m array as the support mics — this evaluates micro-scale receiver interpolation around the array, NOT room-scale receiver generalization** (RAF cannot offer HAA's room-wide receiver spread; HAA's own task is the diagnostic row, §5).
- **Grouping is by the full tx pose line (xyz + quaternion)** — already how the 1,319 groups were counted; q ≡ −q canonicalization applied; the readback audit (§2) confirms whether same-xyz/different-quat groups exist. Contexts therefore always share one physical source pose; dropping the orientation *channel* from conditioning is an approximation (no orientation input exists in FLAC), stated as such — never as exact semantic preservation (C2).
- **Mapping A (AR-style, not in v1):** frame at the listener; context = other tx poses of the same placement (nearest-mic matching, sub-array tolerance; median 9 tx/placement supports K≤8). Tests generalization to **unseen source positions** — RAF's own benchmark task and the one the localization program cares about. Listed in §10 for Yixun to green-light as arm 2 or a separate experiment.

## 4. Coordinate gauge (C3 folded)

- One **literal registered matrix** RAF→pipeline (candidate: (x_p, y_p, z_p) = (X_RAF, Z_RAF, Y_RAF), i.e. front/left/up; pinned, not assumed, at readback) applied identically to tx, rx, and the depth renderer's camera; the panorama pixel→ray equation is written to be **exactly** `convert_equirect_to_camera_coord`'s inverse, and the row order the renderer emits is proven, not `flipud`-copied from HAA (C3).
- **Non-circular verification:** (i) an asymmetric six-wall synthetic fixture with **hand-specified RAF-world rays and analytic distances** as the oracle (the oracle never calls the transform under test); (ii) real-mesh checks — floor/ceiling directions, y=0 ground plane vs camera height (camera height above floor must equal the pose's Y), room-bound sanity, and a landmark bearing check between the two rooms' meshes; (iii) projected-pose translation-only invariant.

## 5. Splits (C1/C6 folded — disjoint, deterministic, published)

- **Unit = one (tx-pose, placement) group (36 captures).** Per room: **N_g = 16 preregistered groups** (deterministic farthest-point selection over tx positions, seeded; Yixun may change N_g, §10.2), each split **12 train / 24 test** (train mics chosen by deterministic farthest-point within the array). Joint finetune over both rooms ⇒ 2×16×12 = 384 train items; test = 2×16×24 = 768 items. Groups are atomic — no capture of a test group's tx appears in training in any role.
- **Val = 4 additional disjoint groups per room** (144 items/room), used ONLY for the every-10-steps val loop; **the reported checkpoint is the preregistered final step-1000 EMA checkpoint — validation never selects it** (C6).
- **Diagnostic HAA-parity row:** one preregistered group per room evaluated separately (12-shot/24-test — the literal HAA analogue; reported with its tiny-n caveat).
- All remaining groups are **held in reserve, listed explicitly** (not claimed as evaluated); the dense all-groups adaptation is Arm B, a follow-up (C1). Split JSONs + per-room counts + support/test distance distributions generated once, seeded, committed to `data/RAF/` as canonical (announcement-01 spirit: never re-cut).

## 6. Finetune + eval recipe (C8/C9/C11 folded)

- Config: `FLAC_RAF_finetune.json` = `FLAC_HAA_finetune.json` clone (lr 5e-6 AdamW, InverseLR, cfg_dropout 0.1, EMA) with `"cond_method": "vanilla"` written into the training config, metrics per §7. Dataset configs clone the HAA ones (`max_context` 8, `max_len` 9600, `force_channels` mono).
- Train (mirrors README verbatim + pins): `--max-steps 1000 --val-every 10 --checkpoint-every 100 --num-workers 8 --batch-size 16` **`--accum-batches 4`** (C9 — README parity restored) `--pretransform-ckpt-path weights/FLAC/VAE.safetensors --pretrained-ckpt-path weights/FLAC/FLAC_EMA.ckpt` (sha256s recorded), bf16-mixed precision, training seed, 1 GPU, frozen VAE. Checkpoint cadence 100 (vs README 10) is a **declared divergence** purely to avoid 100×724 MB of wrapped ckpts; the preregistered final step-1000 ckpt is what's evaluated (C15). Save-dir on the NAS.
- **Eval command (complete, in every manifest, both rows):** `eval_FLAC.py --cond-method vanilla --rotate-deg 0 --cond-autocast default --cfg-scale 1.0 --steps 1 --batch-size <pinned> --num-workers <pinned> --record-stream --expected-stream-count 768 --record-per-scene` on the single canonical RAF test config; full checkpoint loads only (no partial). **C8 deviation, declared:** the review's literal `--frame-avg-angles 0,90,180,270` is a frame-averaging (fa_invariant) mechanism; under `--cond-method vanilla` the registered value is **none/n-a**, recorded explicitly in the manifest and cross-checked against `orbit_provenance` output at the smoke rung — pinning fa angles on a vanilla eval would contradict announcement 05's train/eval-protocol matching.
- **Determinism (C7/C11):** identity audit + stream recording; input hashes must match between the zero-shot and finetuned rows per seed; **eval context draws are deterministic from (capture id)** — a per-item `torch.Generator` seeded by a stable hash, invariant to worker topology and identical across checkpoints and seeds — so the **5 eval seeds (42–46, C9) vary diffusion noise only** (registered estimand), reported as paired mean±SD per metric. Context capture **IDs** (not just positions) are recorded — position fingerprints cannot distinguish RAF's near-duplicate receivers (C7). Training keeps HAA-style stochastic context with seed + worker topology pinned and recorded (C11).

## 7. Metrics (C4/C14 folded)

- **RAF policy added explicitly to the metric stack (TDD):** `"RAF"` joins the supported set in `AcousticMetricsCallback` AND every consumer that branches on `dataset_name` (verified: the callback's fail-closed check at `metric_callback.py:96-98`, the 9,600-vs-8,000 `max_len` branch at `:114` — RAF registers **9,600**, HAA-like — and `RT60Error`'s dataset handling); equal-room (2-room) accumulation; standalone-eval path wired via the dataset config `id` as well as `metrics.dataset_name`. Tests cover init, update, compute, `by_scene` (C4).
- Headline: T60 (subject to the §2 truncation-validity gate), C50, EDT, multires-l1, env — each reported with its RAF-specific window/policy and invalid counts; **not** described as "the standard suite" (C14). `eval_FD:false, eval_retrieval:false`, AGREE ckpt nulled, FD/Recall reported as *unavailable* (no AGREE-RAF exists), never as zero (C14).
- Rows: released-FLAC **zero-shot** on the RAF test split; **finetuned** step-1000 EMA. HAA paper numbers quoted for context only; no cross-dataset comparison claimed.

## 8. Preparation pipeline (C10/C12/C13 folded)

1. `data/RAF/prepare_data.py`: resample 48 kHz→22,050 (librosa, HAA-identical), write **`subtype='FLOAT'` (float32) WAVs** — a declared divergence from HAA's PCM16 default, justified by RAF's ~0.01 peaks (16-bit would put the decay tail ~56 dB above quantization only; measured, not assumed, at readback) — to `<processed>/<Room>/mono_rirs_22050Hz/<id>.wav` (ids stay six-digit **strings**); clipping/NaN checks; quantization/round-trip test (C12). Any scale correction = **one fixed scalar derived from the train support only**, applied identically to targets and context, or none (readback decision rule, §10.4).
2. **Metadata root = `<runtime dataset>/metadata/`** (the loader-visible location HAA's hook infers — NOT `data/RAF/`, which holds only the committed canonical split JSONs; prep writes the runtime copies). Schema: capture id → {tx pose (7), rx (3), group key, placement key, split role, train-pool ids}; large JSONs lazily loaded + cached once per worker (C10).
3. **Depth**: render equirect 256×512 float32 depth from `mesh.obj` at each of the 32+8+2 selected groups' tx positions (v1 needs ~42 renders, not 2,638 — Arm B would need the rest). Renderer dependency (open3d, §10.3) installed only on approval. **QA per emitted map (C13):** finite, positive, exact shape/dtype; ray-hit rate; camera-inside-mesh containment; floor-distance ≈ tx height; room-bounds; value-range audited against AR/HAA depth distributions (the ViT/`GeometryConditioner` normalization expects that scale); ray-miss policy fixed BEFORE rendering; per-worker bounded depth cache in `RAF_md.py`.
4. `RAF_md.py`: HAA_md structure with per-group depth/context; **contract test runs a real batched conditioner pass** asserting target `[1,10240]`, context audio `[8,1,9600]`, `source` `[3]`, `source_vit` `[1,3]`, `context_poses` `[8,3]`, depth `[3,256,512]` float32 finite (C10).

## 9. Calibration, validation ladder, integrity (C16/C7 folded)

- **R-cal (SOP reference calibration, C16):** before any RAF number is interpreted, reproduce the HAA finetune recipe end-to-end on this box (README command, HAA data from Zenodo — acquisition is decision §10.5) and evaluate on the full existing `haa_test.json` (1,282 items, canonical per-room aggregation, 5 generations); compare against the paper's HAA table. Plus real-vs-itself metric sentinels and strict load evidence. Without R-cal, RAF deviations can't be separated from a broken pipeline.
- Ladder: readback (§2) → prep dry-run (one group) → full prep + split hashes → depth QA → smoke finetune (~20 steps; orbit_provenance/flag cross-check; silent-substitution guard exercised) → R-cal → 1000-step run → eval rows. Every run teed to a timestamped log; TDD for all new code in `src/tests/`; universal Codex review per round; runs recorded with params/command/results/reliability files per SOP.
- **Silent-substitution defense everywhere** (C7): `SampleDataset.__getitem__` substitutes a random item on load failure — every RAF run uses the stream audit (`--record-stream --expected-stream-count`), rejects on mismatch, and logs per-item identity.

## 11. Compute & storage (C15 folded — measured-throughput rungs mandated)

v1 is small: prep resamples only selected groups' captures (~1.5k WAVs + reserve enumeration; full-corpus resample deferred to Arm B), ~42 depth renders (~21 MB). Finetune: 1000 steps × accum 4, batch 16, 1×A6000 — README says a 4090 suffices; measured at the smoke rung before the ETA is quoted. Eval: 768 items ⇒ minutes/seed at exp_01's measured rate; 5 seeds × 2 rows trivially parallelizable. R-cal: HAA download + 1000-step finetune + 1,282-item eval ×5 gens — the largest single cost, measured at its own rung. Checkpoints: cadence 100 ⇒ ≤10 wrapped ckpts (~7 GB) on the NAS, pruned to final after eval. Every rung extrapolates from measured throughput; any >12 h projection returns to Yixun before launch.
