REQUEST-CHANGES

C1 — blocking. The proposed split is not HAA few-shot parity. HAA jointly fine-tunes on 12 RIRs per room—48 total—whereas RAF would use 12 per transmitter, approximately 15,828 EmptyRoom examples alone. Either make the first arm genuinely analogous by selecting one preregistered full transmitter pose per room, using 12 spatially distributed references and testing on its remaining receivers, or label the current design “12-shot-per-transmitter dense adaptation” and run it only as a separate follow-up.

C2 — blocking. Grouping by transmitter xyz while dropping quaternion can merge different source orientations, so contexts would no longer be measurements of the same physical source pose. Mono wave-equation reciprocity does not automatically remove directional loudspeaker/microphone effects. Audit quaternions per xyz and duplicate `(tx xyz, rx xyz)` captures; group by canonicalized full pose `(xyz, quaternion)`, treating `q` and `−q` as equivalent. Dropping the orientation channel is defensible for v1 only if each context/test group has one fixed orientation—or measurements show orientation effects are negligible—and must be described as an approximation, not exact semantic preservation.

C3 — blocking. The coordinate test is circular if the same RAF→pipeline transform drives both the renderer and its raycast oracle; any consistently wrong signed permutation will pass. The plan also never states the actual matrix or whether RAF maps require HAA’s `flipud`. Register a literal matrix and panorama convention—for example, if pipeline axes are front/left/up, explicitly test `(x_p,y_p,z_p)=(X_RAF,Z_RAF,Y_RAF)`—then test it with independently specified RAF-world rays in an asymmetric six-wall fixture. On real meshes, verify floor/ceiling directions, front/left landmarks, camera heights, and receiver bearings. The stored pixel-to-ray equation must exactly match `convert_equirect_to_camera_coord`; do not copy HAA’s `flipud` without proving the renderer emits HAA’s original row convention.

C4 — blocking. `metrics.dataset_name = "RAF"` is insufficient and standalone evaluation ignores it in favor of the dataset config’s `id`. `AcousticMetricsCallback` currently rejects anything except `AcousticRooms`/`HAA`; merely adding RAF to that check would still silently select the 8,000-sample path, while `RT60Error` would reject RAF. Add an explicit RAF policy throughout: supported ID, 9,600-sample metric window, T30/invalid handling if justified, equal-room accumulation, and tests covering initialization, update, compute, and `by_scene`.

C5 — blocking. The assertion that onset convention “affects nothing in training” is false. The loader keeps the first 10,240 samples, context and most metrics use the first 9,600, and timing affects direct-path prediction, C50, EDT, and T60 validity. Regress detected onset against geometric distance/c, estimate room/hardware latency and residuals, compare with AR/HAA conventions, and preregister whether only a constant acquisition delay is removed. Also measure T30 validity on the truncated 0.435-second RAF signals versus the full 1.5-second recordings; if invalidity or truncation bias is substantial, T60 cannot be a headline metric.

C6 — blocking. The split specification is ambiguous and statistically underdefined. “Val is a subset of test” conflicts with “test is everything else”; the ≥25 threshold is not derived from K=8 or a stated minimum test size; low-count sources are excluded from the claimed full test; and random 12-shot selection need not reproduce HAA’s spatial coverage. Define mutually disjoint train/val/test partitions, make exact or tolerance-equivalent `(tx pose, rx position)` repetitions atomic, select supports with a deterministic spatially balanced rule, justify the eligibility threshold as `12 + validation/test minimum`, and publish counts plus excluded-source/nearest-context-distance distributions. Validation must never select the reported checkpoint; use the preregistered final step.

C7 — blocking. Full-split evaluation can silently produce plausible numbers on the wrong samples. `SampleDataset.__getitem__` catches load, metadata, and silence failures and substitutes a random item. Every RAF evaluation should therefore use `drop_last:false`, `--record-stream`, `--expected-stream-count <canonical count>`, and `--record-per-scene`; reject any stream-position mismatch and require matching input hashes between zero-shot and finetuned runs for each seed. RAF metadata should expose actual context capture IDs because the existing position-only fingerprint cannot distinguish repeated receiver positions.

C8 — blocking. The announcement-05 protocol is incomplete. The plan omits explicit `--frame-avg-angles`, relies on the training default for `cond_method`, and does not pin the remaining evaluation settings. Put `"cond_method":"vanilla"` in the training config and record a complete command containing at least `--cond-method vanilla --frame-avg-angles 0,90,180,270 --rotate-mode fixed --rotate-deg 0 --cond-autocast default --cfg-scale 1.0 --steps 1`, batch size, workers, seed, stream flags, and the single canonical RAF test config. Do not use partial checkpoint loading.

C9 — blocking. The training/statistical recipe does not mirror HAA. The README command uses `--batch-size 16 --accum-batches 4`, while the plan omits accumulation and therefore changes effective batch, sample exposure, and optimizer dynamics. The paper reports five generations, not three. Restore accumulation 4, pin bf16-mixed precision, training seed, one GPU, frozen VAE, and the exact final step-1000 EMA checkpoint; evaluate seeds 42–46 and report paired mean±standard deviation.

C10 — blocking. The metadata location and per-transmitter schema are not specified sufficiently to satisfy the loader. The plan commits metadata under `data/RAF`, whereas HAA’s hook infers `<runtime dataset>/metadata`; a literal clone will not find it. Define an explicit metadata root and per-capture→full-source-pose→training-pool mapping, preserve six-digit IDs as strings, and lazily cache large JSON structures once per worker. Contract tests must run a real batched conditioner pass and assert target `[1,10240]`, context audio `[8,1,9600]`, source `[3]`, source_vit `[1,3]`, context poses `[8,3]`, and finite float32 depth `[3,256,512]`.

C11 — blocking. A seeded split does not make context draws reproducible. HAA’s `np.random.choice` uses worker-local mutable RNG state, so selections depend on seed, worker count, scheduling, and repeated validation passes. Define whether the five-seed estimand varies diffusion noise only or both noise and context. At minimum, evaluation choices should be deterministic from `(eval seed, target capture ID)`, invariant to worker scheduling, identical between compared checkpoints, and recorded by context ID; training may retain HAA-style stochastic draws with its seed and worker topology pinned.

C12 — blocking. Audio serialization and normalization remain dangerously vague. `sf.write(...wav)` defaults to PCM16, while the 13-GB estimate assumes float32; with RAF peaks near 0.01, subtype and quantization materially affect the decay tail. Specify the WAV subtype, compare the exact post-resample/crop RAF distribution with processed HAA/AR, count files below the loader’s −60 dB silence threshold, and test clipping/NaNs/quantization error. Any scale correction must be one fixed train-support-derived scalar applied identically to target and context audio—not a test-derived or per-RIR normalization.

C13 — blocking. The depth validation omits failure modes that can poison conditioning without an obvious crash: mesh/pose registration errors, cameras outside the mesh, ray misses producing Inf, wrong units, and RAF ranges far outside the AR/HAA conditioner distribution (`GeometryConditioner.max_value=1`). Require every emitted map to be finite, positive float32 with the exact shape; audit hit rate, camera containment, floor distance, room bounds, and pose/depth scale against AR/HAA. Define ray-miss handling before rendering and benchmark a bounded per-worker depth cache rather than repeatedly reading the same 512-KB map.

C14 — should-fix. Omitting FD and retrieval is the correct v1 decision, but the plan should not call the remaining metrics dataset-independent or the result a complete “standard suite.” Set both flags false, remove/null the AGREE checkpoint, mark FD/Recall as unavailable rather than zero, and avoid geometry-consistency claims. Report invalid counts and each metric’s RAF-specific window/policy.

C15 — should-fix. Resource estimates are inconsistent with the design. For EmptyRoom alone, 47,484 minus `1,319×12` gives about 31,656 pre-validation test captures, not 47,484; two similar rooms imply roughly 63k rather than 90k. Checkpointing every ten steps with `save_top_k=-1` retains 100 checkpoints; the released wrapped HAA checkpoint is about 724 MB, implying roughly 72 GB. Accumulation 4, 100 full validation passes at five timesteps, millions of context-file reads, and per-scene metric duplication also undermine the 1–3-hour estimate. Benchmark bounded prep/render/train/eval rungs, extrapolate from measured throughput, and either budget the checkpoint storage explicitly or reduce cadence while preserving a final checkpoint.

C16 — blocking. The SOP-required reference calibration is missing. Before RAF numbers, reproduce the released HAA checkpoint on the existing full 1,282-item `haa_test.json`, with the current evaluation code, canonical per-room aggregation, and five generations—or cite a recent hash-matched reproduction. Add real-vs-itself metric sentinels and strict checkpoint/config load evidence; otherwise RAF deviations cannot be separated from a broken HAA-reversal or metric pipeline.
