# Plan review — exp_11_fa_orbit

1. **BLOCKING — The historical C4 comparator is not a true single-delta control.** Exp_07 C4 was trained on 2×A6000 ([launch record](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_07_fa_scratch_claude/bf_scratch_launch.sh:5)); exp_11 targets 2×L40 ([plan](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/plan_fa_orbit.md:65)). Same seed does not remove GPU/kernel/environment-dependent numerical divergence, which is especially material when training-seed replication is out of scope. **Fix:** train a contemporaneous C4 bridge arm to 40k on the same commit, environment, GPU type, and staging conditions as C8/C16/C32, or run all new arms on the original hardware/software stack. Pin and record GPU UUID/type, CUDA/cuDNN, package hash, source SHA, initializer hash, and first-batch/RNG traces. Without this control, describe the result as a historical cross-run comparison, not an “only orbit changed” causal result.

2. **BLOCKING — R1 changes both training and evaluation orbit, so it is an end-to-end system comparison, not a training-side attribution.** D2/R2 contain the needed four cells but leave the contrasts informal and run R2 only after selecting IMPROVED arms. **Fix:** label R1 explicitly as the bundled train+eval-orbit estimand and, for every Cn arm, pre-register the complete 2×2 at s42/K8: C4-train/a4, C4-train/an, Cn-train/a4, Cn-train/an. Report total effect, eval-side effect, training-side-under-a4 effect, and interaction separately. Do not claim a unique “training-side” mechanism from an informal comparison or only from selected winners.

3. **BLOCKING — The R1 statistics are not valid inferential thresholds as written.** The five evaluations use common seeds, so `sqrt(σ_Cn²+σ_C4²)` incorrectly assumes independence and discards covariance. It is also an SD of eval outcomes, not uncertainty of the mean. Counting “≥4 of 12” treats highly correlated T60/EDT, nested retrieval metrics, and K1/K8 cells as independent evidence and has no calibrated error rate across three arms. **Fix:** compute unrounded, seed-paired deltas from raw JSONs and report their mean, SD, and conditional 95% paired-\(t\) interval (`df=4`). Designate a small set of co-primary cells with an explicit multiplicity rule; keep the 12-cell tiers descriptive if desired. State that all inference is conditional on training seed 42 and does not estimate training-run variability.

4. **BLOCKING — The hypothesis-defining trend readout is subjective.** “Monotone-improving,” “saturating,” and “non-monotone” have no numerical definitions, and the plan does not say what happens when an arm OOMs, is killed, or C32 is not launched. **Fix:** pre-register adjacent-orbit effect estimates and decision thresholds, or drop categorical trend labels and report ordered estimates with paired uncertainty. Missing C32 must yield `NOT ESTIMABLE`, not “saturation” or a negative result.

5. **BLOCKING — The kill rule uses the wrong noise source and would create informative censoring.** Three times C4@40k eval-seed SD does not measure matched-step trajectory noise, training variation, or uncertainty of the Cn screen; consecutive checkpoints are strongly correlated. A stopped arm also has no 40k R1 result and cannot validly be called `DEGRADED`. **Fix:** either retain only hard aborts or define the screen as an economic futility rule using matched-step, common-random-number deltas and a practical-effect margin. Call the outcome `FUTILITY-STOPPED`, exclude it from R1/trend claims, and require the gate evaluation to finish before training advances. Option A currently leaves no GPU for timely screens, so it is incompatible with these gates unless an external evaluation GPU is reserved.

6. **BLOCKING — Filename suffixes and current aggregation do not protect evaluation identity.** `a{n}` records only the angle count, while metric JSONs omit seed, dataset/K, cfg, eval name, split hash, checkpoint hash, and EMA-selection status ([eval record](/n/fs/gatrdp/codespace/FLAC/eval_FLAC.py:53)). The table generator merely counts glob matches and does not enforce unique seeds or inspect protocol metadata ([aggregator](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/gen_model_comparison.py:58)). A malformed eight-angle list, wrong K config, duplicate rerun, or wrong checkpoint could silently enter a C8 row. **Fix:** add TDD-covered provenance fields and fail-closed validation: exact angle values, seeds 42–46 exactly once, existing full K1/K8 config path and hash, 6,337-item split hash/count, cfg 1.0, bf16 autocast, model-config hash, checkpoint hash/global step, and EMA use. Assert checkpoint-embedded `frame_avg_angles` equals the CLI orbit. Re-evaluate the C4 confirmatory block through the same exp_11 harness or provide an audited seed-to-file manifest.

7. **BLOCKING — CPU/float32 synthetic tests do not establish C32 invariance under the actual bf16 path.** `invariant_conditioning` accumulates sequentially in the conditioner output dtype ([implementation](/n/fs/gatrdp/codespace/FLAC/src/data/yaw_rotation.py:294)); cyclically reordered bf16 sums are non-associative, and error can grow substantially from C4 to C32. Thus “exact invariance” may fail numerically even though the orbit is geometrically exact. **Fix:** add an actual CUDA/bf16 integration probe for C4/C8/C16/C32 using the real conditioner, testing every in-group rotation against the base output and an fp32 reference. Pre-register maximum absolute/relative tolerances and use the measured floor in D1/R3. Any change to fp32 accumulation would exceed the “angles only” treatment and therefore requires Yixun approval plus a new C4 control.

8. **BLOCKING — D1 is under-specified and over-interpreted for a C32 spending decision.** “Fixed batch” does not define scene selection, EMA versus online weights, train/eval mode, autocast, tensor normalization, aggregation across the two ViT IDs, or an uncertainty measure. Moreover, headroom measured on a C4-trained network under unseen Cn evaluation protocols cannot establish that C32 training would fail. **Fix:** pre-register a deterministic stratified scene set covering all rooms/types, save its IDs, use EMA/eval mode, report bf16 and fp32 results, define the per-sample/per-conditioner relative-variance equation and scene-level intervals, and treat D1 only as a cost-prior. If C32 is skipped, report the training hypothesis as untested.

9. **BLOCKING — R3 does not currently verify the stated yaw-flatness claim.** It omits the 0° reference, calls all four rotations “out-of-orbit” even though 45° is in C8/C16/C32, 22.5° is in C16/C32, and 11.25° is in C32, and never defines “residual variance.” Aggregate metrics can also remain flat while per-item outputs change. **Fix:** include 0°, label each angle as in-group or off-group per arm, use identical eval noise, and pre-register paired per-item or prediction-level differences plus metric deltas. Either evaluate a common grid over the C4 fundamental sector or narrow the claim to the tested offsets. Encode exact fractional rotations in eval names because the current path suffix truncates them to integers.

10. **BLOCKING — The compute-control statement is factually wrong.** B-V-extend is vanilla, not C4 fa, and therefore cannot be a compute-matched C4 control ([plan](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/plan_fa_orbit.md:20)). No existing curve compute-matches C16 or C32. **Fix:** remove that claim and state that only matched steps/samples are tested; compute efficiency remains unresolved. If a compute-matched conclusion is desired, it requires an actual C4-fa continuation to the empirically matched compute budget.

11. **BLOCKING — The cost and staging model is not yet decision-grade.** If ViT work is exactly 5/6 of C4 cost, linear scaling gives approximately C8×1.83, C16×3.50, and C32×6.83—not 1.95/3.86/7.67. Fifteen steps are also too short unless startup/warm-up is excluded, and the table omits screens, R2/R3, ten confirmatory evaluations per arm, and concurrency interference. **Fix:** time a stated steady-state window after warm-up, record allocated/reserved/external VRAM, run a concurrent probe matching the selected staging option, correct the algebra, and budget every evaluation. Reserve evaluation capacity explicitly; otherwise Option A’s in-flight gates cannot operate.

12. **NIT — The proposed post-wipe hardening preserves a log path, not the log.** A manifest pointing to a deleted worklog file does not retain stdout/stderr. **Fix:** tee the actual log content to both the experiment folder and a durable run directory, and write an atomic pre-launch manifest containing the exact command, SHA, config/checkpoint hashes, environment hash, GPU UUIDs, and output paths.

13. **NIT — `GPUS` and runtime-argument parity need explicit guard coverage.** Config deep-diff does not prove that CLI recipe flags match exp_07. **Fix:** require exactly two distinct validated physical GPU IDs, query those same IDs for VRAM, record their UUIDs, and add a dry-run argv comparison against the exp_07 launch manifest with only the enumerated differences allowed: arm/config identity, GPU selection, logging paths, and 40k stop budget.

14. **NIT — “Best improved arm” is undefined for the optional 67.5k extension.** This permits outcome-adaptive tie-breaking. **Fix:** pre-register a deterministic selector or make the extension a separately planned exploratory experiment; it must not revise the fixed 40k verdict.

**Verdict: REJECT**
