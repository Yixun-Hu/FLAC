# ROUND 4 code review — `exp_11_fa_orbit` screen/backfill and row validator

**Reviewer:** OpenAI Codex (GPT-5, API, independent read-only review) · **Date:** 2026-08-07  
**Reviewed commits:** `a40c733`, `e0da592`, `a6f203a`  
**Verdict:** **REJECT**

The effective eval argv matches the established exp_07/exp_10 protocol, but the resulting artifact is not yet a fail-closed proof of that protocol. Several malformed, mislabeled, partial, or online-weight rows can pass validation or bypass it entirely.

## BLOCKING findings

### 1. EMA is claimed, not proven

The checkpoint gate verifies `global_step` and embedded config but never verifies that `diffusion_ema.ema_model.*` weights exist ([fa_orbit_screen.sbatch:146](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/fa_orbit_screen.sbatch:146)). `eval_FLAC.py` silently falls back to online weights when EMA entries are absent ([eval_FLAC.py:242](/n/fs/gatrdp/codespace/FLAC/eval_FLAC.py:242)), after which the screen sidecar unconditionally writes `"use_ema": true` ([fa_orbit_screen.sbatch:214](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/fa_orbit_screen.sbatch:214)). The validator trusts that assertion.

**Fix:** require EMA entries before evaluation; make `eval_FLAC.py` fail when `use_ema=true` but EMA is unavailable; record the actual selected source (`weights_source="ema"`) in the metrics JSON and validate it.

### 2. The full-split and actual eval protocol cannot be proven from the metrics record

`eval_FLAC.py` tracks the evaluated count in `c`, and `build_metrics_record()` supports `batch_size`/`n_samples`, but the production call supplies neither ([eval_FLAC.py:388](/n/fs/gatrdp/codespace/FLAC/eval_FLAC.py:388)). Every screen therefore writes both as `null`. The validator ignores them entirely.

Seed, dataset config, cfg scale, diffusion steps, eval name, model-config hash, checkpoint hash, and actual EMA selection exist only in a sidecar written by the same driver after evaluation. Thus the validator cannot independently establish that 6,337 items ran or that the sidecar describes the invocation that produced the metrics.

**Fix:** record the actual runtime arguments and outcomes in the metrics JSON: dataset path/hash, seed, cfg, steps, eval name, batch size, evaluated count, model-config hash, checkpoint hash, device, and actual weight source. Require `n_samples == 6337` for both registered unseen configs. Write a pre-eval intent record and cross-check it against this post-eval record.

### 3. Malformed and mislabeled rows pass `validate_row()`

Several explicit counterexamples pass:

- A filename that does not match the schema is accepted because parse failure returns `None` and validation is simply skipped ([exp11_validate_rows.py:100](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/exp11_validate_rows.py:100)).
- The method suffix and `aN` suffix are not validated.
- `rotate_deg` is ignored, so a rotated R3 evaluation can masquerade as an unrotated screen/table row.
- Any nonempty metrics mapping passes; the tests themselves declare only `T60` and `C50` a valid row ([test_exp11_validate_rows.py:43](/n/fs/gatrdp/codespace/FLAC/src/tests/test_exp11_validate_rows.py:43)). Missing required metrics, strings, booleans, `NaN`, and infinities are not rejected.
- JSON duplicate keys and nonstandard constants are accepted.
- Sidecar `model_config_sha256`, `ckpt_sha256`, and `commit` are never checked. `source_sha="unknown"` or any arbitrary nonempty string passes.
- Several sidecar cross-checks are optional when the field is absent.

**Fix:** use strict JSON loading; require the exact six finite numeric table metrics; require `rotate_deg == 0.0` for screen/table rows; require an exact, anchored filename generated by `build_output_paths`; validate all mandatory fields and hashes with strict types. The fractional R3 naming must also be injective—current `_rot{int(...)}` naming cannot distinguish `5°` from `5.625°`.

### 4. Cell integrity and seed policy are caller-controlled

The exactly-once counting works only relative to arbitrary `--seeds` supplied by the caller ([exp11_validate_rows.py:251](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/exp11_validate_rows.py:251)). Tests explicitly bless a two-seed “good” table cell and five rows named `screen` ([test_exp11_validate_rows.py:235](/n/fs/gatrdp/codespace/FLAC/src/tests/test_exp11_validate_rows.py:235)), contrary to announcement 04.

Across rows, the validator does not require identical:

- cell type (`screen`/`conf`/`r3`);
- checkpoint path or SHA;
- model-config hash;
- evaluator source commit;
- orbit implementation source.

The screen driver likewise permits arbitrary seeds while always labeling the cell `screen`.

**Fix:** introduce purpose-specific contracts:

- `futility`: `screen`/`backfill`, exactly seed 42, K=8;
- `table`: `conf`, exactly seeds 42–46, one checkpoint/config/code identity, K=1 or K=8;
- `r3`: rotation-bearing schema, never table-admissible.

Require all cell-level provenance to be identical and add an outer check that table updates include both K cells.

### 5. The validator is advisory, not a gate

After writing the sidecar, the screen emits `SCREENRESULT` without invoking the validator ([fa_orbit_screen.sbatch:199](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/fa_orbit_screen.sbatch:199)). The table generator independently globs and aggregates raw JSONs without calling it ([gen_model_comparison.py:58](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/gen_model_comparison.py:58)). Nothing prevents either consumer from using an unvalidated row.

**Fix:** the screen must run the futility-mode validator before emitting `SCREENRESULT`. `gen_model_comparison.py` must invoke table-mode validation or consume a hash-bound validation manifest and abort regeneration on any failure.

### 6. Checkpoint identity does not establish lineage, especially for backfill

Parsed config equality is a useful gate, and the exp_07 checkpoint tree is correct. It does not prove training seed, originating launch, or file identity. Any checkpoint with a matching config/global step placed under the expected tree passes. The later SHA is self-reported in the sidecar and ignored by the validator; its path check is only a substring test ([exp11_validate_rows.py:189](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/exp11_validate_rows.py:189)).

This does not satisfy plan §5’s audited historical seed-to-file manifest requirement.

**Fix:** bind exp_11 checkpoints to their launch manifest, including arm, seed 42, config hash, run identity, and canonical checkpoint directory. Add a reviewed exp_07 backfill manifest mapping each allowed step to canonical path and SHA-256. Recompute hashes during validation and require all table seeds to use the identical checkpoint SHA.

### 7. Historical loop-vs-batched comparability is not fully qualified or disclosed in the table

The futility comparison itself is coherent because the exp_07 checkpoint is re-evaluated through the current batched path. It does not depend on legacy-loop equivalence.

For direct comparison with existing historical rows, however, the equivalence probe is insufficient to call the difference negligible under production execution. It showed exact equality for B64 full batches and small fp32 differences for B1, but production bf16 B1 and downstream checkpoint metrics were not gated. Existing model-table labels say only “fa eval,” not `legacy-loop` versus `batched`.

**Fix:** label historical rows explicitly as `legacy-loop` and reserve inference for C4L/current batched rows. If numerical interchangeability is claimed, run a production-bf16 tail/full-checkpoint common-noise equivalence check through downstream predictions and metrics.

## NIT findings

### 1. Drift scoping is safe for current dependencies but reopens extension-based holes

`a6f203a` covers the current top-level code/config files, so no present runtime dependency was found outside the gate. However, replacing the recursive experiment-directory pathspec with top-level extension globs excludes future subdirectory helpers, nonstandard extensions, and decision-relevant tracked Markdown/manifests ([fa_orbit_screen.sbatch:121](/n/fs/gatrdp/codespace/FLAC/worklog/worklog_yixun/exp_11_fa_orbit_claude/fa_orbit_screen.sbatch:121)).

**Fix:** retain the recursive directory gate and exclude only known append-only live artifacts such as the active Slurm transcript patterns.

### 2. Backfill admits an unregistered 10k cell

The plan registers matched backfill gates at 20k and 30k; the driver permits 10k as well. It is harmless if diagnostic-only but can be mistaken for registered evidence.

**Fix:** reject 10k or label it explicitly diagnostic and non-gating.

### 3. Guard coverage stops before the dangerous half of the workflow

The 24 shell guards primarily exercise DRYRUN/pre-eval branches. They do not exercise missing EMA, exact argv cardinality, actual eval/tee status, metrics discovery, sidecar correctness, validator invocation, hash tampering, or `SCREENRESULT` suppression. The protocol-flags test checks only a substring, and the suite positively tests seed 43 as a valid screen.

**Fix:** add end-to-end stub-evaluator guards for every post-eval branch and mutation tests for each blocking case above.

## Confirmed-good points

- Effective eval values match exp_07/exp_10: registered full unseen configs for K=1/K=8, own FA orbit, cfg 1.0, one step, bf16 conditioning autocast, and the requested eval seed.
- C4L is byte-identical to the exp_07 B-F config; C8/C16/C32 differ only in `training.frame_avg_angles`.
- The exp_07 backfill checkpoint tree is correct.
- Embedded config/global-step comparison is a strong semantic checkpoint check, though not a complete lineage check.
- The committed evidence reports 226 pytest cases and 24 shell guards green; focused tests and static checks also passed.
- No queue or `outputs_FLAC` mutation was performed.

**Final verdict: REJECT. Do not start screens until the blocking findings are fixed and re-reviewed.**
